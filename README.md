# PX Paper — by pxcheco

A private, browser-first PDF/photo → editable `.docx` converter with a built-in **PX Editor**. Designed for GitHub → Vercel deployment with no API keys, accounts, OAuth, database, or backend setup.

## What it does

- PDF, PNG, JPG/JPEG, WEBP and HEIC input
- Digital PDFs: extracts native editable text instead of OCR when possible
- Scans/photos: OCR with English + Spanish support
- Color-aware OCR
- Approximate layout/alignment reconstruction
- **Smart Edit**, **Clean Text**, and **Pixel Clone** modes
- Generates standard editable `.docx` files
- Built-in **PX Editor** for editing the converted result before download
- PX Editor supports text edits, font family/size, bold, italic, underline, text color, alignment, bullets, numbered lists, undo/redo, print/save as PDF, and DOCX re-export
- PX Editor reads Word run formatting, tables and embedded images from the generated DOCX when available
- Local draft autosave in the browser
- File processing stays inside the browser; the app has no document upload endpoint
- Responsive PX-branded interface

## Deploy to Vercel

1. Upload the repository to GitHub.
2. In Vercel choose **Add New → Project**.
3. Import the GitHub repository.
4. Vercel detects Next.js automatically.
5. Click **Deploy**.

**No environment variables are required.**

## How conversion works

### Digital PDF
PX Paper uses PDF.js to read the PDF text layer and reconstruct editable Word paragraphs. It also inspects PDF drawing operations to approximate text colors.

### Scan / photo
PX Paper renders the page in the browser and uses Tesseract.js (WebAssembly) for OCR. Source pixels around recognized words are sampled to estimate original text colors.

### Pixel Clone
PX Paper adds a rendered copy of the original page plus an editable OCR transcript for maximum visual fidelity.

### PX Editor
PX Editor opens the DOCX generated by PX Paper directly in the browser. It reads the Word XML locally with JSZip, reconstructs editable HTML, preserves supported formatting, and can build a new `.docx` after edits.

## Privacy

The original PDF/photo is processed locally in the browser. No Google sign-in, Drive access, OAuth consent screen, or PX Paper backend is required. OCR/PDF runtime assets may be fetched from pinned public distribution sources, but the user's document bytes stay local.
